# The Fractera marketplace — your side of it

**Process: build.** Searching is asked of the core; buying, installing and offering change the project and wait for the person's yes.
This text comes from the core (one source for every element, written into both templates); the whole map is the core's skill
`marketplace`.

## 1. The three sides

- **The store** — one element on fractera.ai: the catalogue of starters, search, the storefront, applications and their research, the
  checkout. It never calls a project.
- **The client «Маркетплейс»** — a native element in every project: the person's recommendations (keep · delete · «в корзину»), the cart
  (one copy of a starter), the history of choices, search in its own bot.
- **The core** — the project's identity and every signed call to the store, the payer's window, the install after payment.
- **You** — never one of them: you ask, the person decides, the core acts.

## 2. You need a hand nobody here has

Raise `need` (skill `need-capability`) with what for, in your own words. The core climbs its ladder: your brothers → the store → Lagrix
(simulated today) → a build. «Рекомендовано, ждёт решения человека» means rows in the person's list of recommendations, never «куплено».
Go on with your task as if the hand will come later, or ask the person — never wait in silence.

## 3. The person asks you to find or buy a starter

Pass their words to the core with `need`, or tell them where to ask: the client's bot, or «найди в маркетплейсе …» to the main bot.
A purchase is the person's own act in the core's window: one payment per cart, by card on Fractera's checkout. You never take a card,
pay, open a checkout, install a starter or call the store.

## 4. The person wants to offer this element

- **An own native element** (born from the native template): «Предложить в маркетплейсе» in Build → f2f — Web2 (Fractera) or Web4
  (Lagrix, simulated) → the application form. The creator checks every application personally, then the research, then publication with
  the author mark.
- **A custom element does not offer itself** (Roma, 2026-11-24, step 854).
- **What the store takes** (R-02): the element's name and its repository's name end with «starter»; the Fractera build structure; a
  repository of the author, private, its token given on the store's own page — never through a door, a chat or a file.

## 5. What is sold, and the money

Starters only — the minimum sufficient function for further development, told plainly; a ready solution is never sold (R-01). One copy
per buyer: a bought starter installs again for free (R-05). The author sets a one-time price; free starters exist; shares 50/50; no
refund unless the law requires it — a failed install is repeated for free. Whoever pays buys for the whole project.

## 6. What works today (the core's skill `marketplace` §8 keeps the newest state)

The store's search v2 answers live, its catalogue empty. The client element, the purchase, the install and the sending of applications
are being built (core step 862): say so plainly — the application form keeps the application in the project until the store's door
answers.

## 7. Never

Buy, pay, install or call the store yourself; send a key or a token anywhere; promise a price, a seller or a guarantee the store did not
return; tell a simulated rung as a real offer; put a look-alike in place of the store's honest «nothing yet».
